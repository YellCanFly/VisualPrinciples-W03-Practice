# 设计四原则交互实践网站开发方案

版本：2.0  
日期：2026-10-14  
项目目录：`Footages/W03/W03-Practice/`  
产品暂名：视觉排布实验室

网站由“四原则对比”和“自由实践”两个主要界面组成。用户先观察亲密性、重复、对比、对齐带来的视觉变化，也可以直接打开空白画布，自定义文字、添加基础图形、修改背景颜色，通过拖拽和属性调整完成自由排布，再查看四项评分及百分制综合反馈。

实践区没有指定主题、必需文案或预设内容关系。所有元素均可添加、编辑和删除。网站采用纯前端静态架构，支持 GitHub Pages，无需登录，作品可保存在本地浏览器或导出为文件。

## 1 页面范围与入口

顶部导航保留“观察对比”“自由实践”“我的作品”，使用帮助放在右上角。默认首页为观察对比，主按钮为“打开自由画布”；用户也可以通过实践页链接直接进入编辑器。

| 界面 | 内容 | 主要操作 |
| --- | --- | --- |
| 观察对比 | 四原则标签、两版视觉效果、差异说明、辅助线 | 切换原则、前后比较、调整演示参数 |
| 自由实践 | 元素库、图层、画布、属性面板 | 自定义文字、添加图形、改色、拖动、删除 |
| 分析结果 | 四维分数、综合分、评分覆盖情况、定位建议 | 查看依据、定位元素、返回修改 |
| 我的作品 | 本地缩略图、名称、保存时间 | 打开、重命名、复制、删除、导入导出 |

分析结果作为编辑器右侧面板，详细结果可展开；不要求跳转到独立流程才能继续编辑。用户可以随时切换观察与实践，已有作品自动保存。

## 2 四原则对比界面

### 2.1 共同结构

上方依次显示“亲密性、重复、对比、对齐”标签。中央左右并排展示“调整前”和“调整后”，下面给出简短解释以及一个可操作参数。窄屏使用同位置切换，两版保持同一画布比例和缩放。

演示采用中性的示例文字，如“文字 A”“文字 B”“一段说明文字”，配合基础几何形状，不赋予活动、海报或其他特定主题。同一对比中的文字内容、元素数量和画布尺寸一致，尽量只修改与当前原则相关的属性。所有示例均为本项目原创。

“显示分析线”默认关闭，开启后展示距离、边缘或重复样式标记。动画约200毫秒，支持关闭及减少动态效果设置。进入自由实践直接打开用户的画布；另提供“复制此示例到新画布”，复制后的全部元素都可自由修改和删除。

### 2.2 四组演示

| 原则 | 调整前 | 调整后 | 可操作参数与提示 |
| --- | --- | --- | --- |
| 亲密性 | 文字块与图形均匀散开或聚成难以区分的一团 | 元素形成清楚的视觉组，组内接近、组间分开 | 调整组内/组间间距；显示分组轮廓及测量线 |
| 重复 | 相似元素的字号、颜色、描边处理不一致 | 部分颜色、字形或图形规则重复出现 | 切换样式统一程度；高亮重复的视觉特征 |
| 对比 | 文字大小、粗细和图形大小相近，色彩明暗差异小 | 大小、粗细或明暗产生清楚差别 | 分别调节字号差、图形大小差和颜色；区分层级差异与可读性 |
| 对齐 | 元素边缘及文字锚点存在零散偏移 | 元素通过左边缘、中心线、右边缘或基线建立联系 | 开关参考线，切换左轴/中心轴/双列示例 |

页面另提供一组综合对比，逐步改变同一组无主题元素，展示多个原则可以同时起作用。各步骤可随时切换，不设置作答、解锁条件或成绩记录。

设计依据及源材料定位见[参考资料与设计依据](./参考资料与设计依据.md)。

## 3 自由实践界面布局

### 3.1 初始画面

首次进入显示白色空白画布，默认960×640逻辑单位，文件名“未命名作品”。画布外的提示为“从左侧添加文字或图形”，添加第一个对象后消失。提示不是作品元素，不出现在导出文件中。

左侧元素库可直接点击添加，也可拖入画布。第一次添加文字时自动进入文字编辑状态。所有内容均由用户自行输入或选择，不需要先选择主题、填写目标、声明语义分组或完成其他表单。

### 3.2 区域安排

| 区域 | 默认尺寸 | 内容 |
| --- | --- | --- |
| 顶部工具栏 | 高56像素 | 文件名、保存状态、撤销、重做、新建、分析、导出 |
| 左侧面板 | 宽208像素 | “添加元素”“图层”两个标签；基础文字与图形入口 |
| 中央工作区 | 自适应 | 画布、缩放、适合窗口、网格与吸附开关 |
| 右侧面板 | 宽280像素 | 选中对象的属性；未选中时显示背景颜色与画布设置 |
| 分析面板 | 复用右侧或展开 | 四维分、综合分、问题依据与定位操作 |

桌面推荐1280×720及以上。1024像素宽时可折叠侧栏；平板横屏使用可切换面板。手机上提供平移画布和抽屉面板，工具按钮维持可点击尺寸，不随画布缩小。

点击画布空白处取消选择，右侧自动切换为画布属性。图层列表支持选中被覆盖的元素。评分辅助线与选框属于工作区覆盖层，不写入作品。

## 4 元素与属性设计

### 4.1 文字

“添加文字”生成内容为“输入文字”的文本对象，选中全部占位内容，用户可直接替换。支持中文、英文、数字、换行、粘贴及中文输入法。双击文本或点击右侧“编辑文字”进入编辑状态。

| 属性 | 功能 |
| --- | --- |
| 内容 | 完全自定义，不与示例文案比较 |
| 字体 | 两种本地可再分发字体，支持中文与拉丁字符 |
| 字号 | 默认24，允许12–120逻辑单位 |
| 字重 | 根据实际字体提供常规与粗体等可用值 |
| 文字颜色 | 预设色板、颜色选择器和HEX输入 |
| 段落 | 左/中/右对齐，行距1.0–2.0 |
| 文本框 | 调整宽度后重新换行，高度自动计算；不拉伸字形 |
| 位置与层级 | X/Y、置顶、置底、上移、下移 |

文本对象没有强制的标题、正文或说明角色。可以重复相同内容，也可输入完全不同的内容。清空文字后保留正在编辑的文本框，退出编辑时删除空对象；一次撤销即可恢复。

### 4.2 基础图形

首版提供矩形、圆角矩形、圆、椭圆、三角形、菱形、直线、箭头和五角星。图形按钮配小图标与中文名称。

| 图形属性 | 行为 |
| --- | --- |
| 大小 | 输入宽高或拖动尺寸手柄；圆默认等比，其他闭合图形可切换等比 |
| 填充 | 纯色或无填充 |
| 描边 | 颜色、粗细、无描边；直线与箭头至少保留可见描边或填充 |
| 圆角 | 圆角矩形开放圆角值，限制在几何合法范围 |
| 线段与箭头 | 拖动端点，调整长度与方向；箭头随端点更新 |
| 位置与层级 | 移动、置顶、置底、上移、下移 |

首版闭合图形保持轴向，不提供自由旋转；斜线和箭头由端点定义方向。后续可扩展旋转、透明度、渐变及图片。无填充且无描边的对象提示“当前不可见”，允许用户继续调整或删除。

### 4.3 背景

背景是画布属性，不占图层、不计为前景元素、不能通过Delete删除。右侧提供颜色选择器、HEX输入、最近使用颜色与“恢复白色”。修改背景立即更新画面，并使旧评分标记为待更新。

图形可以自由作为文字底板或装饰，评分根据实际图层关系解析文字背后的颜色。背景色和对象颜色使用相同色板交互。

## 5 编辑交互与状态

### 5.1 添加 选择与移动

从元素库点击添加时放置在当前可视画布中心，连续添加略微错开位置；拖入时按释放位置放置。新增元素自动选中。每幅作品最多40个前景对象，达到上限后说明原因，用户可自由删除任意对象。

单击选中、Shift单击增减多选、空白处拖动框选。移动选区时保持对象之间的相对位置。按方向键移动1个逻辑单位，Shift加方向键移动10个；右侧X/Y字段和点击式微移按钮提供无需拖动的操作。

视图缩放范围25%–200%，提供100%与适合窗口。空格加拖动平移工作区，文字编辑时空格正常输入。画布缩放和平移不改变存储坐标与评分结果。

### 5.2 复制 删除与排列

| 操作 | 行为 |
| --- | --- |
| 复制 | 按钮或Ctrl/Cmd+D，生成新ID，稍作偏移并选中新副本 |
| 删除 | 删除按钮或Delete/Backspace，作用于选中对象；文字编辑中保留字符删除行为 |
| 全选 | 画布获得焦点时Ctrl/Cmd+A，文本输入框内只全选文字 |
| 清空画布 | 一次清除全部前景对象，保留背景，提供立即撤销入口 |
| 对齐 | 多选后可左/中/右、上/中/下对齐；单选可选择相对画布对齐 |
| 等间距分布 | 至少三个对象时提供水平、垂直分布 |
| 图层顺序 | 列表拖动或属性按钮修改z顺序 |
| 锁定 | 用户可临时锁定和解锁，锁定对象仍参与评分；无预设不可删除对象 |

吸附默认开启，可随时关闭或按Alt临时关闭。候选线来自其他对象的边缘、中心及画布边缘；吸附距离建议6个屏幕像素，评分容差独立使用逻辑坐标。斜线、箭头的吸附基于端点及几何边界。

### 5.3 撤销 重做与版本

一次拖动、一次颜色选择提交或一次连续文字输入形成一个历史操作。Ctrl/Cmd+Z撤销，Ctrl/Cmd+Shift+Z重做；支持Windows常用Ctrl+Y。保留最近100个命令，超过后淘汰最早记录，界面明确边界。

“保存版本”由用户主动执行，可自定义名称。每次分析另保存对应场景与报告，最多保留10次普通分析快照。用户可选任意两版并排比较，不存在必须完成的版本顺序、锁定阶段或说明文本。

增删或修改元素后，旧分析报告保持在历史中，当前面板显示“画面已修改，请重新分析”。拖动时不连续弹出扣分信息。

## 6 四维评分与结果界面

### 6.1 自由画布的分析方式

评分读取当前对象的几何位置、间距、文字样式、图形样式、色彩和图层。系统自动寻找视觉分组、重复特征、明显差异及共享对齐线，不要求用户为对象标记角色或事先选择排版骨架。

| 维度 | 可观察依据 | 反馈定位 |
| --- | --- | --- |
| 亲密性 | 几何分组、组内距离与组间距离 | 显示推断的组和间隔；不判断文字语义是否相关 |
| 重复 | 字体、字重、颜色、形状、描边等特征复现 | 高亮共享特征及孤立样式；不要求所有元素相同 |
| 对比 | 字号、尺寸、粗细、明暗差异以及文字可读性 | 显示差异和文字/背景对比；不假定某段文字必须最突出 |
| 对齐 | 多个对象共享的边缘、中心线或基线 | 显示支持该判断的参考线，允许左/中/右和多列关系 |

所有可评维度均为0–100分。这些分数描述当前算法识别到的视觉结构，不能证明内容表达正确或涵盖所有审美判断。具体计算、可评条件与异常处理见[评分规则](./评分规则.md)。

### 6.2 综合分与不足状态

四项都可评时，显示“四维综合参考分”，采用四维等权平均，满分100：

```text
综合分 = round((亲密性 + 重复 + 对比 + 对齐) / 4)
```

某一维度缺少可判断证据时显示“—”及原因，不按0分惩罚，也不默认满分。此时只对可评维度求平均，标题改为“部分维度参考分”，同时显示“已评估2/4项”等覆盖说明；全部不可评时不显示数值。空画布提示添加元素，单元素不伪造四维满分。分项仅有部分子指标可评时，保留数值并标明“证据有限”，列出未评内容。

例如三项分别为80、70、90，另一项缺少证据，则显示“部分维度参考分80/100，已评估3/4项”。不同覆盖情况的分数不直接作升降比较；删除元素后即使覆盖减少，也不自动提示“设计进步”。

删除任何元素均是合法编辑，重新按当前画面计算。越界、不可见及遮挡显示为明确的画面检查提示，按评分规则影响参与样本和结果状态。评分只针对当前场景，不把与过去版本相比少了元素视为内容缺失。

### 6.3 结果呈现

面板先显示综合结果，再用四条等长条形图展示分项，条目旁标明可评状态。缺少证据的条目显示灰色占位，不用空进度条冒充0分。报告记录当前对象数量、分析版本和时间。

首屏最多显示三条建议，点击后高亮相关对象和测量线。例如“这三段文字的左边缘分别位于120、128、121，可尝试统一左边缘”；亲密性使用“按位置识别到两个视觉组”，避免直接断言用户的内容归属。

反馈只解释与定位，由用户决定是否调整。面板提供“重新分析”和“返回属性”，不自动将画面排列成标准布局。

## 7 本地作品与文件

### 7.1 保存与恢复

编辑提交后约800毫秒自动保存到IndexedDB。工具栏区分“保存中”“已保存到此浏览器”“保存失败”。切换作品或新建前立即提交待保存状态，不能等防抖计时结束后误写到另一作品。保存失败仍保留内存作品，提供下载JSON。刷新后恢复最近成功记录，保留上一份记录用于恢复损坏写入。

数据库与偏好键使用项目命名空间，如 `w03-design-lab-v2`。同一文件多标签编辑时提示冲突并允许恢复为新副本。清理浏览器数据或结束无痕会话可能丢失记录，跨设备使用通过JSON导入导出。

“我的作品”支持打开、重命名、复制、删除。删除后提供撤销。新建始终创建独立空白作品，不覆盖已打开作品。

### 7.2 导入导出

| 文件 | 内容 |
| --- | --- |
| `作品名.design.json` | 当前画布背景、全部元素及样式、版本号和对应当前画面的报告，可继续编辑；历史版本可分别导出 |
| `作品名.png` | 作品画面，默认2倍尺寸，包含背景，无编辑选框和辅助线 |
| `作品名-分析报告.html` | 自包含作品预览、四维及综合结果、可评覆盖、反馈依据和分析版本 |

报告不包含额外必填文本。所有用户内容转义后写入HTML。导出当前分析报告前检查场景修订号，未分析或报告过期时先分析，再使用该次场景快照和对应结果生成文件；缺少证据的项目如实显示原因。历史报告使用其自身快照，不能将新画面配旧得分。PNG生成前等待字体与文字布局就绪，使用共享场景渲染结果；必须验证中文、换行、基础图形和图层顺序与画布一致。

JSON导入检查schema版本、文件大小（建议2MB）、最多40个元素、ID唯一性、坐标及尺寸合法性、颜色、字体ID和字符串长度。首版每文本最多1000个字符，画布最多10000个字符；输入时先提示并阻止超限，导入使用相同限制。

只导入本项目结构化JSON，不执行HTML、脚本或外链资源。文字内容可以任意改变，不对照预设文案。导入成功后创建新副本并重新评分，不直接信任文件里的旧得分。JSON不内嵌PNG、字体或全部历史，用户可选择任一历史版本单独导出；导出前验证文件符合相同大小与字段限制并可回读。不支持的新版本给出提示并保留当前作品。

## 8 视觉与可访问操作

工具界面使用浅色背景、清楚边框和少量强调色。用户画布与工具区视觉分开，背景调色仅影响作品。主要入口使用文字加图标，避免只依赖图标记忆操作。

| 项目 | 建议初值 |
| --- | --- |
| 页面背景 / 面板 | `#F5F6F8` / `#FFFFFF` |
| 主文字 / 次级文字 | `#172033` / `#475569` |
| 边框 / 强调色 | `#D6DCE5` / `#1D4ED8` |
| 字号 | 界面正文16、辅助14、页标题24–28像素 |
| 间距 | 4、8、12、16、24、32像素等级 |
| 点击区域 | 主要控件至少40×40 CSS像素，保持清楚的焦点和选中态 |
| 圆角 | 6–8像素，画布外使用轻微阴影 |

工具界面检查文字对比、键盘可达性和焦点显示。普通界面文字与背景以至少4.5:1为基准，大字按标准条件检查；作品中的低对比表现由用户控制，并在分析中提示。[W3C文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

Tab按区域移动焦点，Esc退出文字编辑或取消选择。图层列表、X/Y数值和点击微移提供拖拽替代方式，色板配HEX输入，反馈配文字说明。输入框保留正常文本快捷键。[W3C拖动替代说明](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

## 9 技术实现约定

### 9.1 架构

采用React、TypeScript、Vite和HashRouter，SVG承载作品与辅助线，HTML负责工具栏、属性、文字编辑和结果。Pointer Events统一鼠标与触控输入。评分使用独立TypeScript函数，保存使用IndexedDB，偏好设置使用localStorage。

作品数据、视图状态与命令历史分离。SVG `getScreenCTM().inverse()`负责坐标换算，拖动在动画帧更新，松开时提交一次命令。Pointer cancel和窗口失焦清理拖动状态。

SVG文字以 `text/tspan` 表示，中文输入通过HTML textarea完成。统一换行和测量函数服务渲染、评分与导出，不能用空文本框宽度伪造可见文字的对齐。斜线与箭头保留端点，闭合图形保存几何类型及宽高。

实施时选相互兼容的稳定依赖，提交lockfile并固定Node版本，CI执行 `npm ci`。[Vite环境要求](https://vite.dev/guide/)

### 9.2 字体与导出

本地字体需要覆盖支持范围内的中文、英文和数字，不只包含演示文案。字体许可随项目保存。用户输入未覆盖字符时显示缺字提示，允许继续编辑和保存JSON；正式评分与PNG导出等待字体问题解决，不能用缺字方框冒充正常结果。

PNG采用共享几何与字体的导出链；可将SVG序列化并嵌入所需字体，或用经验证的离屏Canvas重绘。首个技术验证必须确认中文换行、线条箭头、描边和文字背景一致，再固定实现方案。首版不引入用户外链图片，避免跨域资源使画布无法导出。

### 9.3 数据结构

| 对象 | 关键内容 |
| --- | --- |
| SceneDocument | schemaVersion、documentId、名称、修订号、画布尺寸/背景、元素、保存时间 |
| TextElement | ID、位置、文本框宽度、任意文本、字体、字号、字重、行距、颜色、段落对齐、z顺序 |
| ShapeElement | ID、几何类型、位置、尺寸或端点、填充、描边、圆角、z顺序 |
| ViewState | 缩放、平移、选中ID、网格与吸附开关，不参与评分 |
| ScoreReport | 场景修订及指纹、规则/布局/字体版本、四维值或null、可评原因、覆盖度、综合分、定位证据 |
| Snapshot | 场景深拷贝、可选名称、对应报告、时间，不引用可变对象 |

分析从当前SceneDocument推导关系，不存储题目ID、必需元素ID或固定语义关系。用户手动锁定只影响编辑操作，不能使对象免于分析。每次修改生成新修订号，异步计算完成时检查修订号，避免旧结果覆盖新画面。

## 10 GitHub Pages 部署方案


### 10.1 部署形态

GitHub Pages 托管构建后的 HTML、CSS、JavaScript 和静态资源，浏览器承担编辑与评分。只发布 `dist/`；源课件、整本 PDF、用户作品与本地缓存不进入构建产物。[GitHub Pages 介绍](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

推荐让 `W03-Practice` 作为独立仓库的根目录，项目源码在用户指定的本地路径保持不变。如已有课程总仓库，不在其中直接新建嵌套仓库，应采用下列总仓库方式，或在确认仓库边界后再单独发布。

| 情况 | 工作流位置 | 构建工作目录 | 上传路径 |
| --- | --- | --- | --- |
| 独立项目仓库 | 仓库根 `.github/workflows/pages.yml` | `.` | `dist` |
| 课程总仓库 | 总仓库根 `.github/workflows/pages.yml` | `Footages/W03/W03-Practice` | `Footages/W03/W03-Practice/dist` |

总仓库中的 `defaults.run.working-directory` 只作用于 shell 步骤。Node 缓存 lockfile 路径、路径过滤与上传 artifact 路径仍需填写相对仓库根的完整路径。不能把工作流仅放在子项目的 `.github/workflows/` 后期望 GitHub 自动发现。

### 10.2 路径与路由

如果站点最终地址为 `https://<用户名>.github.io/<仓库名>/`，Vite `base` 为 `/<仓库名>/`。用户或组织主页根域站点、根目录自定义域使用 `/`。若站点刻意发布到另一个子目录，按最终 URL 的实际前缀设置。`base` 不能从本地 `Footages/W03/W03-Practice` 路径直接推导。[Vite 静态部署指南](https://vite.dev/guide/static-deploy.html)

路由采用 `/#/learn/proximity`、`/#/practice`、`/#/review/<documentId>` 等 hash 形式，部署后实际位于上述 base 后。第三种链接的作品来自本机存储，另一设备打开时应显示“本机没有该作品，请导入文件”，不能把它当作作品共享链接。

资源通过 import 或 `import.meta.env.BASE_URL` 拼接；避免写死 `/assets/...`。部署验收必须覆盖字体、演示数据、图标、返回入口及刷新后的深层链接。

### 10.3 发布流水线

1. 在目标仓库确认默认分支和 Pages 设置，选择 GitHub Actions 发布。
2. 检出代码，安装与项目约定一致的 Node，使用 lockfile 执行 `npm ci`。
3. 运行类型检查、lint、必要单元测试和构建；端到端检查作为合并或发布门禁。
4. 使用官方 Pages 配置、上传、部署 actions；授权 `contents: read`、`pages: write`、`id-token: write`，配置 `github-pages` environment 和发布并发组。
5. 发布 `dist` artifact。构建失败不覆盖线上版本，成功后记录 URL 与提交号。
6. 在真实 Pages URL 验证深层链接、编辑、保存、字体和导出。需要回退时重新发布上一个验证通过的提交。

具体 action 版本在实施时从官方文档核验并固定，禁止无约束使用 `@main`。[GitHub 自定义 Pages 工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

本次交付不需要仓库名即可完成方案。实施到部署阶段再读取实际 remote、分支与 Pages 地址配置，避免预设错误路径。

## 11 功能验收

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| F01 | 首次进入自由实践 | 直接显示空白画布，能添加对象，无主题选择或其他必填步骤 |
| F02 | 自定义文字 | 中文输入、换行、粘贴、改写和清空正常，既有文字均可替换 |
| F03 | 基础图形 | 九种图形可添加、调整、改色和删除，斜线与箭头端点响应正确 |
| F04 | 背景颜色 | 可选色和输入HEX，重开、导出后保持一致 |
| F05 | 拖拽与选择 | 单选、多选、图层选择、移动、对齐、分布均符合操作 |
| F06 | 自由删除 | 任意对象均可删除，清空后为空画布，撤销能恢复；不出现必需文案校验 |
| F07 | 缩放 | 50%、100%、150%视图下无指针漂移，作品坐标及分析结果一致 |
| F08 | 四维分析 | 分数及证据对应当前画面；不足项显示原因；覆盖减少不伪装为进步 |
| F09 | 自由布局 | 居中、多列、纯图形和混合画面不因缺少预设角色被拒绝 |
| F10 | 保存恢复 | 刷新恢复最近成功保存；失败可见；导入不覆盖当前作品 |
| F11 | 导出 | JSON回读保持内容与样式，PNG中文及图形无缺失，辅助线不导出 |
| F12 | 版本比较 | 快照不随当前编辑改变，无强制实验阶段或说明输入 |
| F13 | 可访问操作 | 通过键盘和数值控件完成选择、移动、调色、删除、分析、导出 |
| F14 | Pages | 子路径与hash链接可刷新，字体和资源无404，无后端依赖 |

评分回归样本覆盖空画布、单对象、稀疏对象、紧密分组、重复图形、多种合法对齐、完全重叠、不可见文字和纯图形。固定规则/字体/布局版本下，评分不受浏览器窗口或画布缩放影响。

性能目标为40个元素内拖动流畅，常见操作帧耗时目标低于16.7毫秒，分析目标300毫秒内，PNG导出目标2秒内。主JavaScript gzip目标不超过350KB，字体另设预算并实测。以上是开发验收目标，最终在目标浏览器设备测量。

## 12 首版交付范围

首版完成四组原则对比、一组综合演示、无主题自由画布、自定义文字、九种基础图形、背景颜色、选择和拖拽、增删复制、属性修改、对齐分布、撤销重做、四维及综合反馈、本地保存、文件导入导出与GitHub Pages部署。

后续可独立扩展自由旋转、透明度、渐变、用户图片、更多画布比例及SVG导出。账号、云存储和实时协作需要另行引入服务端，不是当前静态页面的运行依赖。

本次交付为页面功能及实现方案，后续源码继续放在本项目目录。
